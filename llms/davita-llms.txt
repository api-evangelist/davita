# DaVita

> DaVita Inc. is a Fortune 500 kidney care provider running in-center hemodialysis, home
> hemodialysis and peritoneal dialysis programs in the United States and abroad, plus transplant
> support, integrated kidney care, hospital partnerships and clinical research. DaVita runs no
> developer program and publishes no API documentation — but its own web platform serves a live,
> public, unauthenticated REST API at https://www.davita.com/wp-json/, including a first-party
> `davita/v1` namespace. This file was generated by API Evangelist from that machine-readable route
> index; it is not published by DaVita.

Generated: 2026-09-05 by API Evangelist (https://apievangelist.com). Method: generated from
https://www.davita.com/wp-json/ and the artifacts in https://github.com/api-evangelist/davita.

## API

- [WordPress REST route index](https://www.davita.com/wp-json/): The contract. Self-describing;
  lists every route, its methods and its arguments. This is the only machine-readable definition
  DaVita serves.
- [OpenAPI (derived by API Evangelist)](https://github.com/api-evangelist/davita/blob/main/openapi/davita-wp-rest.yml):
  OpenAPI 3.1.0, 100 paths / 230 operations, transformed mechanically from the route index above.
  DaVita does not publish an OpenAPI.
- Base URL: `https://www.davita.com/wp-json`
- Auth: none for reads. Write routes require WordPress Application Passwords or a cookie nonce and
  are staff-only, so the practical surface is read-only.
- Errors: WordPress `{code, message, data.status}` envelope, not RFC 9457.
- Paging: `page` / `per_page` (1-100) / `offset`, with `X-WP-Total` and `X-WP-TotalPages` headers.
- Rate limits: none published, and no rate-limit headers are returned.

## First-party endpoints (davita/v1)

- `GET /davita/v1/find-a-center?location=` — dialysis center locator; `location` is required,
  optional `lat`, `lng`, `modalities`.
- `GET /davita/v1/find-a-class?location=` — Kidney Smart education class finder; filters for
  language, in-person vs online, days and time.
- `GET /davita/v1/usda/search?food=` — food search returning kidney-relevant nutrients: calories,
  protein, sodium, potassium, phosphorus. Proxied from USDA FoodData Central.
- `GET /davita/v1/usda/food/{fdcId}` — one food record with the same nutrient panel.
- `GET /davita/v1/video-details`, `GET /davita/v1/playlist-details` — video metadata.

## Not published

- No developer portal, no API documentation, no getting-started guide, no API reference.
- No OpenAPI, AsyncAPI, GraphQL, gRPC or WSDL published by DaVita.
- No MCP server (mcp.davita.com does not resolve; /mcp is 404 on every host).
- No A2A agent card: /.well-known/agent-card.json and /.well-known/agent.json return 404 on every host.
- No /.well-known/ documents at all — security.txt, api-catalog, openid-configuration and
  oauth-authorization-server are 404 everywhere.
- No SDKs, no CLI, no Postman collection, no sandbox, no status page, no API changelog, no pricing.
- No public FHIR endpoint. api.davita.com resolves and is a real gateway, but returns an
  empty-bodied 404 on every probed path, including /fhir and /fhir/metadata.

## Caveats for agents

- This is a content and locator API, not a clinical one. Nothing on the public surface carries
  patient data, and nothing here should be used for clinical decision-making.
- The API is undocumented and unversioned in practice. DaVita has made no compatibility promise and
  publishes no deprecation policy, so treat every route as able to change without notice.
- Nutrient values are relayed from USDA FoodData Central; DaVita is the reshaper, not the source.
